# 报告质量优化

本轮只优化合成离线研究报告，不调用 YouTube 或 Qwen，不修改真实分析权限。

## 数据与复用

新增 41 条自编合成记录、三个虚构品牌和未知品牌。覆盖台阶/梯子/平整池底、大小泳池、不同污物/维护场景、重复痛点、价格咨询、内容反馈、间接反馈、品牌歧义和同条相反观点。
同一批数据经过现有 CSV 校验、反馈资格筛选和 Mock 分类，32 条进入产品体验分析；9 条未纳入并在附录保留原因。
32 条中 DemoAqua 12 条、DemoPool 10 条、DemoTerra 8 条、未知品牌 2 条，均为自述且未核验购买。
`qualify_batch` 仅增加可选 catalog，使用原有筛选规则；默认 Demo 目录和旧接口不变。
`analyze_batch`、`generate_insights` 和 `render_report` 校验继续复用。后者只用于验证一致性，不将通用报告附到专属报告后。

## 属性与需求聚类

`research_quality.py` 以人工标准化属性进行可复现的需求分组，使用场景按已验证的原文引句精确匹配。
Navigation & Obstacle Handling 覆盖导航、障碍区卡住和缆线缠绕；Reliability 保留电机故障等一般失效。
这是研究 sidecar 细分，不改变旧分类枚举、提示词或检查点签名。细分注释必须与旧分类对应，并有文本依据。
当前扩展注释为每条一个重点属性；多属性旧记录仍可显示原属性，但不允许用单个重点注释覆盖多个不相干属性。
属性/场景/需求标注都是人工合成测试标签，不是模型能力评估结果，也没有自动进行语义聚类。

痛点记录和明确需求人数分开计数。明确需求必须有逐字表达（目前检查 I need/want/wish/require），且来源原文存在；不把“不好用”自动转成明确需求。
潜在需求、改进和差异化方向明确为人工 Mock 解释，只是供访谈、复现和对照实验验证的假设。
同评论同属性同情绪只计一次；Mixed 同时贡献一次正面和负面，分子不可相加当作人数。

## 两种报告的差别

Product Improvement Research：以问题属性为主线，展示场景、证据量、明确需求数量、潜在需求、改进方向、验证方式和反证。
单条痛点也允许保留，但明确为探索性假设、证据不足。排序仅按样本问题提及量，不是商业机会评分。

Competitor Research：先展示品牌覆盖与同属性正负提及/基数，再聚焦具有多品牌共同场景的记录。
对相同方向明确注明“未观察到品牌认知差异”；只在方向不同时指出描述性线索，不作显著性或因果判断。
没有共同场景时，不输出品牌差异，保留待验证研究问题。无样本的 Brand A/B/C 不出现在专属报告。

两份报告均以前置 Executive Summary、关键发现及研究建议为起点。正文仅有 E 证据链接；完整原文只在附录出现一次。
附录保存方法、合成 ID、属性情绪、明确需求引句与筛选排除记录，不附通用报告全文。

## 能力边界

所有记录都是人为设计，不能推断市场规模或品牌表现。原文真实性、问题复现、严重度、用户优先级、价格敏感度、购买意愿和 ROI 均未验证。
共同场景的文字相同，不代表环境、产品版本、操作方式受到控制；无法形成可靠竞品排名。
推断来源是 human_mock；旧字段 ai_inference 仅因兼容性保留，报告已说明不是模型生成。本轮没有真实 AI 推断。
实际 Qwen 的需求提取、聚类稳定性、多语言能力和幻觉率尚未由这些测试验证。
Navigation 的细分标签和固定编辑建议尚不能自动推广到其他产品品类。
普通报告中的不足 20 条品牌样本提醒沿用，但不是统计显著性保证或市场代表性标准。

## 验收覆盖

原有测试继续运行；新增质量测试覆盖共享数据、41→32 筛选、两报告差异、无通用报告重复、导航/可靠性细分、Mixed 去重、明确需求与痛点人数分离、单条假设、占位品牌排除、共同场景门槛、相同方向不强造差异、证据锚点、虚构引句/需求拒绝、无依据属性改标拒绝和真实数据拒绝。

CLI：`python -B Agent/consumer_needs.py --purpose both --expanded`。
旧的三条样例 API 仍保留兼容性；新版评审请使用 expanded 共享样本。
