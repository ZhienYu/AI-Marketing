# Week 03 (10.27) | Product Insight Agent MVP 开发

## 一、本周完成了什么

### 1. 确定 AI Agent 的产品方向

正式开始开发 **Product Insight Agent**，目标是帮助海外市场营销人员分析消费者评论，识别用户痛点、产品优势和竞争品牌差异，最终生成市场调研报告。

确定了两个核心分析方向：

- **Consumer Insights**：消费者情绪、产品痛点、正面反馈和未满足需求。
- **Competitive Intelligence**：不同品牌的优势、弱点及潜在市场机会。

原本计划直接通过 Reddit、Amazon、YouTube 等平台获取评论，但考虑到 API 权限、数据获取难度和开发成本，决定先使用合成评论完成核心分析流程，再接入真实数据。

在原来的 `AI-Marketing` GitHub 仓库中新建了 `Agent` 文件夹，存放项目需求、Python 程序和测试数据。

### 2. 完成数据处理与 AI 评论分类

先准备了 9 条模拟的泳池清洁机器人评论，分为 Brand A、Brand B、Brand C 三个品牌。

使用 Work 辅助开发 Python 程序，逐步实现：

- **Data Validation**：检查 CSV 字段、无效评论、重复记录及品牌归属。
- **AI Classification**：调用 Qwen API 分析评论的整体情绪、正面反馈和消费者痛点。
- **Product Aspect Classification**：将不同表达统一归类到 Battery Life、Cleaning Performance、Maintenance、Price 等标准产品属性。
- **Batch Analysis**：批量分析多条评论，并记录 Token 使用量。
- **Resume Analysis**：跳过已经成功分析的评论，避免重复调用 API。

通过真实 Qwen API 成功验证了单条和多条评论的分析功能。

### 3. 配置并调用大模型 API

使用阿里云百炼北京地域的 Qwen API。

了解到**云服务器与大模型 API 是独立的服务**。虽然之前购买的服务器位于新加坡，但本地程序仍然可以调用北京地域的模型接口。

使用 `.env` 文件保存 API Key，并通过 `.gitignore` 防止密钥被上传到公开 GitHub 仓库。

首次调用遇到了 Python 的 SSL 证书验证失败问题。通过检查网络连接和 Python 安装环境，发现问题与本地 Python 证书配置有关，完成修复后成功调用 Qwen。

这次也开始理解 API 请求、HTTPS 证书验证、Token 消耗以及模型调用成本之间的关系。

### 4. 实现消费者洞察与竞品统计

开发 `generate_insights.py`，将 AI 对单条评论的分类结果汇总成品牌比较数据。

例如，可以统计不同品牌在 Battery Life、Maintenance、Price 等方面获得了多少正面和负面反馈。

其中学习到一个重要的数据分析原则：

**同一条评论即使多次提及同一产品属性，也不能在同一情绪类别中重复计数。**

例如，一条评论同时提到维护困难和清洗过滤器耗时较长，虽然包含两个具体问题，但在 Maintenance 负面属性的评论数量中只计算一次。

### 5. 自动生成市场调研报告

开发 `generate_report.py`，将统计结果自动整理成 Markdown 报告，包含六个部分：

1. Executive Summary
2. Consumer Pain Points
3. Consumer Sentiment
4. Competitive Intelligence
5. Business Opportunities
6. Sources & Methodology

报告可以展示品牌比较、消费者痛点、原始评论编号和待验证的商业建议。

由于目前使用的是合成数据，报告明确标注 `DEMO — SYNTHETIC DATA`，并提示样本量不足，不能把结果当作真实市场结论。

目前已有 **64 项离线自动化测试通过**，Agent 的主要分析流程已经基本建立。

## 二、本周学到了什么

### 1. AI Agent 不只是调用大模型

之前对 AI Agent 的理解比较简单，认为只要接入大模型 API，就能够自动完成任务。

实际开发后发现，一个完整的 AI 应用通常需要多个环节：

**数据输入 → 数据验证 → AI 分类 → 统计分析 → 报告生成**

大模型主要负责理解非结构化文本，而 Python 程序负责数据处理、统计、结果验证和流程控制。

### 2. API 分为不同类型

这次理解了两类 API 的区别：

- **LLM API**：例如 Qwen，负责分析和理解消费者评论。
- **Data Source API**：例如 Reddit 或 YouTube 的接口，负责获取原始数据。

目前已经完成大模型 API 的接入，但尚未接入外部数据平台。

### 3. 为什么需要 Mock Testing

Mock Testing 使用预先准备好的模拟结果，不需要调用真实 API。

它的价值在于先检查程序能否正常处理数据、生成文件，以及应对异常情况。

但也认识到：**程序测试通过，不代表 AI 的分析一定准确，更不代表分析结论具有商业价值。**

因此后续仍然需要真实评论和人工检查。

### 4. 结构化数据对商业分析的重要性

消费者可能使用不同的措辞描述同一个问题，例如：

- Short battery life
- Battery dies too quickly
- Needs frequent recharging

如果只记录原始句子，很难汇总统计。

将这些表达统一归类为 **Battery Life**，才能进一步比较不同品牌的消费者反馈。

这让我更直观地理解了数据标准化与商业分析之间的关系。

### 5. AI 辅助开发的工作方式

这次主要通过 Work 编写和修改 Python 程序，自己负责明确需求、理解功能、运行程序和检查结果。

逐渐形成了一套开发流程：

**提出需求 → AI 编写代码 → 自动化测试 → 本地运行 → 检查结果 → GitHub 版本管理**

相比直接要求 AI 一次性生成整个产品，按模块逐步开发更容易定位问题，也更容易理解各部分功能。

## 三、遇到的问题

**问题 1：Python 无法连接 Qwen API**

最初出现 `CERTIFICATE_VERIFY_FAILED`。虽然 `curl` 能收到服务器响应，但 Python 无法验证 HTTPS 证书。

检查后发现使用的是官网安装的 Python 3.13，修复证书配置后成功调用 Qwen。

**问题 2：重复调用造成不必要的 Token 消耗**

最初批量分析会重新处理已经完成的评论，因此增加了 Resume 功能，通过已有结果识别并跳过成功记录。

**问题 3：测试数据与正式数据容易混淆**

为了方便未来接入真实评论，将运行结果区分为：

- `outputs/test/`：合成数据测试结果。
- `outputs/real/`：未来真实数据的分析结果。

同时继续通过 Git 忽略规则保护密钥、运行结果和敏感数据。
