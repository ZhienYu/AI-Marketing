## 1. Today's Objectives

今天的主要目标有两个：

2. 推进 Phase J 模型对比实验，验证新一代 Qwen 模型是否能够提升消费者反馈分析的准确性、信息覆盖率和商业洞察质量。

相比之前主要关注报告页面和功能实现，今天的工作开始转向模型能力评估、实验设计和系统可靠性。

## 2. Phase K — Dashboard Finalization

今天首先完成了 Phase K 的最终优化和验收。

此前的 Dashboard 虽然已经能够展示消费者主题、需求与痛点、购买决策和研究启示，但仍然存在摘要内容重复、商业机会不够具体，以及页面颜色和布局较为单调的问题。

本次主要完成以下改进：

- **Executive Summary：** 从简单展示几张洞察卡片，调整为综合呈现本轮观察、证据覆盖、关键数字和后续研究方向。
- **Evidence Transparency：** 明确展示独立评论数量、视频来源数量，并区分多个发现是否来自同一条评论。
- **Content Organization：** 减少消费者主题、需求与痛点、购买决策等章节之间的不必要重复。
- **Business Implications：** 将商业机会拆分为消费者反馈、商业意义、建议下一步和证据限制，使报告更加容易理解。
- **UI/UX：** 调整整体配色、卡片布局、章节导航和证据交互，让 Dashboard 更接近专业商业研究软件。

在最后的证据核对中，还验证了 Soundcore 与 Pixel Buds Pro 2 的反馈没有发生错误归属，并正确区分消费者本人体验、购买咨询和第三方转述。

最终，Phase K 的正式改动通过测试，并以 Git commit `4be6092` 推送到 GitHub `main` 分支。

**Learning Reflection**

这次我认识到，一份好的 AI 商业研究报告不能只依赖信息数量和视觉设计。

真正有价值的报告应该帮助用户迅速理解：

- 发现了什么？
- 有多少证据支持？
- 对企业可能意味着什么？
- 下一步应该研究什么？

同时，报告越像专业产品，就越需要主动呈现证据限制，避免让单条评论看起来像已经被验证的市场结论。

## 3. Phase J — Preparing the Model Benchmark

Phase K 完成后，开始推进 Phase J。

这一阶段计划比较：

- **Baseline:** `qwen-plus-2025-12-01`
- **Candidate:** `qwen3.6-plus-2026-04-02`

设计是让两个模型分析相同的 12 条真实 YouTube 评论，覆盖 Wireless Earbuds、Air Purifier、Smartphone Battery 和 Robotic Pool Cleaner 四个产品领域。

评估不仅包括 JSON 和 Schema 合格率，还包括事实准确性、信息覆盖率、产品归属、证据支持、最终报告保留质量和模型成本。

我学习到，**模型对比不仅是比较两段 AI 回答，而是一次需要控制输入、处理规则、评分标准和数据来源的实验。**

如果两个模型采用不同的输入或后处理方式，即使最后的报告质量不同，也很难判断差异是否真正来自模型。

## 4. Model Compatibility and Validation

今天进行了 Qwen 3.6 的接口与结构验证。

第一次真实候选模型请求返回了可解析的 JSON，但未通过本地结构联合检查。由于原始响应在规定期限内被清除，无法确定具体失败原因。

随后完善了评测诊断机制，将评论映射、原始 Schema、生产规范化后的 Schema 和证据引用检查分开记录。

这一过程中发现，评测器与生产系统曾存在校验口径差异。生产系统支持部分字段规范化，而旧评测流程可能直接把这些输出判为失败。

在修复并完成离线测试后，使用 3 条合成评论进行了第二次真实 Qwen 3.6 兼容性测试。

结果：

- API 调用成功。
- JSON Object 正常解析。
- 3/3 条评论正确映射。
- 3/3 条通过原始与规范化后 Schema。
- 证据引用有效，未发现产品归属错误。

这证明候选模型能够在当前接口配置下正常运行，但并不能证明它的消费者洞察能力优于现有模型。

**Learning Reflection**

我认识到，验证 AI 系统时必须区分：

**模型输出错误、格式校验错误、Python 后处理错误，以及最终报告展示错误。**

这些问题可能产生相似的表面结果，但需要完全不同的解决方法。

## 5. Fixing a Purchase-Intent Detection Issue

在合成兼容性测试中，还发现了一处 Python 后处理漏判。

例如：

“这款耳机值得多付 20 美元吗？”

模型已经正确识别了购买咨询，但本地规则没有识别这一表达方式，导致有价值的消费者购买线索没有进入报告。

随后修复了购买咨询识别规则，并通过离线回归验证：

- 价格差异咨询可以保留在购买决策研究中。
- 咨询不会被误认为已经购买或实际使用。
- 正式产品属性统计仍然保持严格的验证门槛。
- 无关评论与没有证据支持的内容不会因为规则调整而被错误接纳。

**Learning Reflection**

这让我进一步理解到，**模型的分析结果与最终 Agent 输出并不是一回事。**

即使模型正确识别了某项消费者需求，如果 Python 处理规则过于严格或分类不完整，这项信息仍然可能在最终报告中消失。

因此，改进 Agent 不能只考虑更换更强的模型，还需要检查整个数据处理链路。

## 6. Real-Data Benchmark Challenges

随后尝试准备正式 A/B 模型对比所需的真实评论。

样本设计是四个产品领域各 3 条，共 12 条，并在模型调用前冻结人工参考事实点。

实际执行过程中遇到了两个问题。

**第一，样本获取和冻结存在衔接问题。**

Air Purifier 和 Smartphone Battery 能够获得新的真实评论，但执行流程曾错误地要求新评论匹配历史评论的具体事实描述，而不是根据通用的产品相关性和证据标准选择样本。

这导致部分符合初筛条件的新评论没有进入最终逐条核实和参考答案冻结阶段。

**第二，15 分钟的数据保留窗口增加了实验执行难度。**

本项目需要在规定窗口内完成数据核实、参考点冻结、模型请求、结果评分和清理。

一旦实验提前停止，原始评论和模型响应会被删除，下一轮往往需要重新获取数据。

本次虽然完成了购买咨询规则修复和新的样本搜索，但未能完成 12 条样本与人工参考答案的最终冻结，因此没有启动正式 A/B 模型对比。

截至今天，尚不能判断 Qwen 3.6 与当前 Qwen Plus 哪个分析效果更好。

## 7. Key Lessons Learned

今天最大的收获主要有三个。

**First, evidence quality matters more than presentation complexity.**

报告是否可信，不取决于卡片数量或可视化效果，而取决于每条发现是否有准确来源、是否正确解释了消费者行为，以及是否明确展示不确定性。

**Second, model performance and system performance must be evaluated separately.**

一个模型可能正确提取信息，但 Python 后处理可能将其删除。只有分别评估原始模型输出和最终报告，才能找出真正的改进方向。

**Third, a reliable experiment needs a reliable execution workflow.**

这次反复中止让我意识到，仅仅设计好样本数量、模型参数和评分指标还不够。

还需要提前验证数据采集、人工标注、模型调用、结果评估和数据清理能否在规定时间内完整执行。

否则即使各个组件都正常工作，整个实验也可能无法完成。

## 8. Next Steps

下一阶段将优先完成 **Phase J End-to-End Benchmark Workflow Rehearsal**。

计划使用完全合成的数据，先离线模拟完整实验流程：

- 验证新样本能否按照通用标准筛选。

- 模拟 8 次模型请求及完整 A/B 盲评。
- 检查各阶段耗时以及 15 分钟限制。
- 确认停止条件和数据清理机制。

只有完整流程经过验证，才重新进行真实评论采集和付费模型对比。

长期来看，希望在消费者评论分析稳定后，进一步探索视频内容与评论的联合分析，但目前仍应优先解决核心分析质量与实验可靠性。

今天标志着项目开发重心的一次转变。

此前我主要关注如何让 Agent 自动运行、生成报告并拥有专业的用户界面；现在开始更多思考如何证明分析结果是准确、可靠和有商业价值的。

我逐渐认识到，**开发 AI Agent 不只是调用大语言模型，而是设计一套从数据获取、证据验证、模型推理到商业决策支持的完整系统。**

Phase K 已经完成并冻结。Phase J 虽然还没有产生正式的模型比较结果，但今天解决的兼容性、诊断和后处理问题，为后续开展可靠的模型评估打下了基础。
